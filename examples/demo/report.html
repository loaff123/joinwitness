05

Method & privacy

Local computation. Portable evidence.

Read the result with these assumptions

  • Keys use exact strings. No trimming, type coercion, fuzzy matching, or deduplication is applied.
  • SQL NULL behavior: a NULL in any key component prevents a match, even against another NULL.
  • Relationship checks cover all non-NULL keys in both inputs, including keys without a match.
  • Predictions are calculated from key frequencies. The actual joined dataset is never materialized.
  • Keys are exact strings; there is no trimming, coercion, or deduplication.
  • Any configured NULL key component prevents a match; NULL-key rows count as unmatched rows, not distinct keys.
  • Relationship uniqueness is checked over every non-NULL key, including unmatched keys.
  • Expansion counts extra copies of left rows; only the ten largest expansion groups are shown.
  • Monetary values, when selected, are validated on every left row and summed exactly without rounding.

Private by default

  • This self-contained report works offline. It contains no scripts, external fonts, trackers, or remote resources.
  • Source paths, column names, full input rows, and key hashes are not included.
  • Key values and unmatched-key samples are withheld. Expansion groups use anonymous labels.
  • Aggregate counts and selected amount totals may still be sensitive. Share only with an appropriate audience.

A preflight describes the configured join and rules. It cannot establish whether the selected keys, input data, or business assumptions are correct.
